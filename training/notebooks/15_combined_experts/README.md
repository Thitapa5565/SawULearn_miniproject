# ฝึกโมเดลจาก expert01 + expert02

เปิด Notebook ด้วย VS Code และเลือก kernel ของ **`.venv` ในโฟลเดอร์ที่โคลน**
หรือเลือก `.venv/Scripts/python.exe` ที่ราก repository

## อ่านตามลำดับ

1. **01_train_combined_experts.ipynb** — ตรวจข้อมูล, label/feature, น้ำหนัก, CV แยกคลิป, ค้นพารามิเตอร์, เลือกด้วย validation, fit รุ่นสุดท้าย, ความสำคัญ feature และภาพต้นไม้
2. **02_validation_results.ipynb** — ผลของรุ่นที่ฝึกด้วย train เท่านั้น: Tree/Forest/Dummy, train–val gap, confusion matrix, precision/recall/F1, ผลรายคน/คลิป, ภาพที่ทายผิด และการตรวจสองอาการพร้อมกัน
3. **03_test_results.ipynb** — ผลของรุ่นสุดท้ายที่ฝึกด้วย train+val: คะแนน test, landmark coverage, confusion matrix, ผลรายคน/คลิป, ตัวอย่างผิด, การตรวจพร้อมกัน และช่วงความแปรปรวนจาก clip bootstrap

Notebook ที่รันเสร็จบันทึกตารางและกราฟไว้ในไฟล์ จึงเปิดอ่านได้โดยไม่ต้องรันใหม่
หาก Run All ค่าเริ่มต้นในเล่ม 01 จะโหลดผลการค้นและโมเดลของ run เดิม

## การทดลองรอบใหม่

ในเล่ม 01 ตั้ง `TRAIN_NEW = True` และปรับ `TREE_GRID` / `FOREST_GRID`
แล้ว Run All จะสร้างโฟลเดอร์ run ใหม่ ให้คัดลอก RUN ที่พิมพ์ออกมาไปใส่เล่ม 02 และ 03 ก่อนประเมิน

ปรับค่าจาก train CV และ validation ก่อนเท่านั้น เมื่อเห็น test แล้วอย่านำคะแนน test ไปเลือกค่าซ้ำ
หากทดลองซ้ำหลังเห็น test ต้องรายงานว่าชุด test เดิมเคยถูกเปิดแล้ว และควรเก็บผู้เล่น/คลิปใหม่สำหรับยืนยันผล

## วิธีอ่านผล

- `usable`: เฉพาะเฟรมที่ landmark/feature ครบ
- `all reviewed`: รวมเฟรมที่ผู้ตรวจเลือกแต่ landmark ไม่ครบ ซึ่งนับเป็นประเมินไม่สำเร็จ
- `frame_accuracy` / `frame_macro_f1`: ทุกเฟรมมีน้ำหนักเท่ากัน
- `clip_balanced_accuracy` / `clip_balanced_macro_f1`: ทุกคลิปมีน้ำหนักรวมเท่ากัน เพื่อลดอิทธิพลคลิปยาว
- `coverage`: สัดส่วนเฟรมที่ feature ครบ; ตารางหลักแสดง coverage แบบถ่วงน้ำหนักคลิปด้วย
- `exact_match`: ทายก้มหน้าและไหล่เอียงถูกทั้งคู่ในเฟรมเดียวกัน
- `joint_recall`: ในเฟรมที่มีสองอาการจริง ตรวจพบทั้งสองได้กี่ส่วน

ผล validation ใช้ estimator ที่ fit train อย่างเดียว ส่วน test ใช้ estimator ที่ refit train+val แล้ว
จึงต้องอ่านคำอธิบาย split ควบคู่กับคะแนนเสมอ

## สิ่งที่รอบนี้ทำ

ใช้ชุดข้อมูล `expert01_expert02_20261007` ที่ตรวจแล้ว:

| งาน | train | validation | test | feature ที่ลอง |
|---|---:|---:|---:|---|
| ก้มหน้า / ไหล่เอียง | 833 | 258 | 268 | 10 ตัว ทั้งสองงาน |
| จับพอดี / สูง / ต่ำ ในท่าขวาสุด | 168 | 52 | 53 | เปรียบเทียบ 2 กับ 4 ตัว |
| ควรปรับองศาการสี: มุมผิดหรือสีลอย | 261 | 83 | 77 | 4 ตัวจากลำตัวและมือ |

240 ชุดค่า × 3 TRAIN folds = 720 ครั้งที่ fit ระหว่าง CV
จากนั้น shortlist Tree/Forest อย่างละหนึ่งแบบต่อหนึ่งงาน แล้วเลือกด้วย fixed validation

แหล่งโค้ดประกอบบทเรียน: `training/src/training/combined_experts.py`
แหล่งสร้าง Notebook: `training/src/training/build_combined_notebooks.py`
ข้อมูล run ที่บันทึก: `run.json` ในโฟลเดอร์นี้
ผล CSV/JSON/PNG: `training/reports/<RUN>/`
โมเดล: `training/models/<RUN>/validation/` และ `training/models/<RUN>/final/`

## ขอบเขตการตีความ

ข้อมูลมีผู้เล่นสองคน โดยทั้งสองคนมีคลิปใน train/validation/test จึงเป็นการทดสอบคลิปที่กันไว้ของคนเดิม
ไม่ใช่การทดสอบคนใหม่ทั้งคน ส่วน expert01 บาง split เคยผ่านการทดลองก่อนหน้านี้แล้ว
งานคันชักใช้ตำแหน่งร่างกายเป็นตัวแทน ไม่ใช่การวัดนิ้วบนด้ามหรือระยะคันชักถึงหย่องโดยตรง
คะแนนรอบนี้เป็นผลคลาสจากโมเดล ยังไม่รวม guard/การรวมคำทำนายหลายเฟรมของหน้าเว็บ

**การฝึกและประเมินไม่เปลี่ยนโมเดลที่เว็บไซต์ใช้อยู่**
